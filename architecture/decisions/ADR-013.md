# ADR-013: State in LangGraph checkpoints (SQLite) carried as workflow artifacts; resume on re-run

**Date:** 2026-11-23
**Status:** Proposed
**Decision area:** D4 State
**Supersedes:** ADR-004

## Context

ADR-004 kept state in state.json and started every re-run from scratch. With LangGraph, the SqliteSaver
checkpointer stores the full state after every node. GitHub Actions artifacts survive between jobs of a run and
between attempts when a job is re-run. The code written so far lives in git, not in the state, so a fresh runner
would lose it.

Options considered:
1. Keep ADR-004 (fresh start on every re-run)
2. **SqliteSaver at out/checkpoints.sqlite, uploaded as the build artifact (overwrite); a re-run build job downloads it, restores the code from state.patch (git diff base..HEAD saved after every commit), and continues at the pending node; rework reads the build thread's final state**
3. Commit state files to the PR branch
4. External database

## Decision

We will checkpoint after every node and carry the checkpoint file as a workflow artifact. Re-running a failed
build job resumes at the node that was running; the reviewer job never downloads it.

## Consequences

- A crash late in the run does not repeat (or re-pay for) earlier stages; tested locally: crash at merge -> resume at merge, same token total.
- State is inspectable after the run (state.json + checkpoints).
- Artifact retention (90 days) limits how long a run can be resumed.
- Repo setup must be re-applied before resuming (found by the local crash test: missing excludes deleted .venv).
