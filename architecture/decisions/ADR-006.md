# ADR-006: Fast model for the builder, stronger different model for the reviewer

**Date:** 2026-11-23
**Status:** Proposed
**Decision area:** D6 Models

## Context

The builder makes many calls per run (4 stages + retries); the reviewer makes one call per round. Only a Gemini API key is
available. Using the same model for builder and reviewer risks correlated blind spots.

Options considered:
1. Same model everywhere
2. **Builder `gemini-3-flash-preview`, reviewer `gemini-3-pro-preview` (fallback 2.5-flash / 2.5-pro)**
3. Different vendors for builder and reviewer

## Decision

We will use the Flash model for all builder stages and the Pro model for the reviewer, configured in `autose/config.yaml`
so experiments can swap them without code changes.

## Consequences

- Most tokens go to the cheaper, faster model.
- Reviewer differs from builder in model, prompt, job and permissions.
- Same vendor/family means errors may still be correlated.
- Tested in experiment E1 (same-model vs different-model reviewer).
