# ADR-016: A stage-4 failure still stops the run, but hands the code to a human as a draft PR

**Date:** 2026-11-24
**Status:** Accepted
**Decision area:** D7 Checks / D9 Safety and failures

## Context

The assignment requires that "a stage should hand over to the next one only after its check has passed" and that
a stage that cannot pass its check "should explain why in its artifact and stop the run". Runs 45351202045 (issue
#4) and 45379575388 (issue #1) stopped at stage 4 with correct code (4/4 hidden tests in both cases), blocked by a
wrong acceptance criterion and by existing fixture tests. The human only had artifacts to read, with no branch or
PR to inspect, fix and merge by hand.

Options considered:
1. Stop with artifacts only (previous behaviour)
2. Continue to release + review with a warning (breaks the stage-gate rule)
3. **Stop (status failed, no CI wait, no review), but push the branch and open a DRAFT PR titled "DO NOT MERGE
   (N failing tests)", labelled `autose:tests-failing`, listing the failing tests and the stop reason**

## Decision

Option 3 (fork PR #15), behind `budgets.draft_pr_on_test_failure` (default on). Finalize labels the issue
`autose:failed` and links the draft PR.

## Consequences

- The stage gate and "stop the run" rule hold; the hand-off is visible on GitHub.
- A draft PR with failing tests could be merged by mistake: mitigated by the title, the label, draft status, the
  failing-test list and the CODEOWNERS ruleset (a human must approve).
- Signal to revisit: draft PRs pile up unreviewed, or one is merged without the failing tests being resolved.
