# ADR-015: Existing tests may change only when the design declares them, citing the AC that requires it

**Date:** 2026-11-24
**Status:** Proposed
**Decision area:** D5 Tools / D7 Checks (amends the role separation of ADR-005)

## Context

ADR-005 lets the implementer change only `src/`; any edit under `tests/` is reverted, so an agent cannot weaken
tests to make them pass (this worked in run 45347324270). Run 45379575388 (issue #1) showed the other side: the
issue asks for behaviour that upstream's own fixtures forbid (`tests/fixtures/table.txt`, "Invalid Table"). The
implementation was correct (4/4 hidden tests) but could never pass the suite, because a correct PR must update 8
existing tests. The graph looped implement x2 + redesign and stopped (5.5M tokens, $0.55).

Options considered:
1. Keep tests read-only; such issues always end in "needs human"
2. Let the implementer edit any test when existing tests fail
3. **The design stage declares existing test/fixture files under `## Existing tests to update`, each citing the AC
   that requires the new behaviour; code checks the file exists and the AC id is real; implement may edit `src/`
   plus exactly those files; the reviewer must check each such change; the PR body lists them for the human**

## Decision

Option 3 (fork PR #14). If existing tests fail, nothing is declared and the implementer keeps its code, the graph
goes straight to redesign with feedback on how to declare, instead of another implement loop.

## Consequences

- Behaviour changes that contradict existing tests become possible, with a visible, AC-linked trail.
- A wrong declaration (an AC that does not really require the change) can still weaken a test; the reviewer and
  the human are the remaining checks.
- Signal to revisit: a declared update changes expectations unrelated to the cited AC.
