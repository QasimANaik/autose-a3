# ADR-012: Control flow as a LangGraph StateGraph with code-decided conditional edges

**Date:** 2026-11-23
**Status:** Proposed
**Decision area:** D2 Control flow
**Supersedes:** ADR-002

## Context

ADR-002 chose a hand-written Python state machine. Adding parallel workers (fan-out with Send, fan-in at merge),
checkpoints and resumable runs by hand would duplicate what LangGraph already provides, and the maintainers already
run LangGraph in SpecBridge, so they can read the graph.

Options considered:
1. Keep the hand-written state machine
2. **LangGraph StateGraph: nodes = stages, conditional edges = routing functions that read check results (last_ok, attempts, loops), Send for parallel workers, explicit loop-back nodes; review graph is a second small StateGraph run in its own job**
3. An LLM planner node that chooses the next stage
4. Separate Actions workflows triggering each other

## Decision

We will express the pipeline as a LangGraph StateGraph. Every conditional edge is a plain Python function over
check results and counters; no model chooses the route. Review rounds stay unrolled as fixed Actions jobs (the job
graph cannot loop); the rework job runs the same main graph again in mode=rework.

## Consequences

- Graph structure is inspectable (nodes/edges) and matches the diagram.
- Parallel fan-out/fan-in and checkpointing come from the framework.
- Adds a dependency (langgraph 1.2.20) installed in every job.
- Signal to revisit: framework behaviour (e.g. recursion limit, Send semantics) causes failures that plain code would not.
