# ADR-014: One cheap model (gemini-3.5-flash-lite) for every agent node

**Date:** 2026-11-24
**Status:** Accepted
**Decision area:** D6 Models
**Supersedes:** ADR-006

## Context

ADR-006 chose a fast builder model and a stronger, different reviewer model. Real runs changed the inputs:
`gemini-3-pro-preview` is not on Google's pricing page and `gemini-2.5-flash` is retired for new keys
(run 45236521564); the current Pro model (`gemini-3.1-pro-preview`, $2.00 / $0.20 / $12.00 per 1M tokens) has no
free tier. The first real build run (45347324270) used 4.16M input tokens (81% cached) and 31k output, so cost is
driven by cached input and the number of turns, not by output. The assignment allows the same model for the
reviewer ("You can use a different model for the reviewer if you like, although this is not required").

Prices (Standard paid tier, per 1M tokens, in / cached / out; aistudio.google.com/docs/pricing, 2026-11-24):
gemini-3.1-pro-preview $2.00 / $0.20 / $12.00; gemini-3.8-flash $0.75 / $0.075 / $3.75;
gemini-3.5-flash-lite $0.30 / $0.03 / $2.50 ("optimized for high-volume agentic tasks");
gemini-3.1-flash-lite $0.25 / $0.025 / $1.50.

Options considered:
1. Keep ADR-006: Flash builder + Pro reviewer (about $1.00 per issue, billing required)
2. Lite builder + Flash reviewer (about $0.40 per issue, reviewer still a different model)
3. **gemini-3.5-flash-lite for every agent node, gemini-3.1-flash-lite as fallback (about $0.30 per issue)**

## Decision

Every agent node (understand, design, implement, test workers, e2e worker, reviewer) uses
`gemini-3.5-flash-lite`; the fallback for a call that fails before doing any work is `gemini-3.1-flash-lite`.
Reviewer independence relies on the other layers of ADR-008: its own job with a read-only token, its own
adversarial prompt, no builder artifacts, and the evidence rule enforced by the judge node.

## Consequences

- About 3x cheaper per issue than ADR-006; all models have a free tier (daily request limits still apply).
- Builder and reviewer may share blind spots (correlated errors), so the reviewer can be weaker at catching the
  builder's mistakes. The seeded PRs measure this directly.
- A Lite model may need more retries on the harder issues (#2 regex, #5 vague).
- E1 (weak reviewer) now differs only in permissions and prompt, not in model.
- Signal to revisit: the reviewer misses planted bugs in the seeded PRs that a stronger model would catch, or the
  retry rate makes runs cost more than a stronger model would.
