# ADR-005: Tools via Gemini CLI built-ins restricted by policy files; GitHub access only via gh CLI in code

**Date:** 2026-11-23
**Status:** Proposed
**Decision area:** D5 Tools

## Context

Agents need to read and edit code and run tests. GitHub write access (push, PR, review) is dangerous in an agent
exposed to untrusted issue text. Gemini CLI 0.70 has a policy engine (allow/deny/ask_user; ask_user = deny in headless mode).

Options considered:
1. GitHub MCP server given to the agents
2. Agents call `gh` themselves
3. **Agents get only file + test tools via an admin-tier policy file per role; all GitHub actions (push, PR, review, labels) are done by orchestrator/publish code with `gh` and GITHUB_TOKEN, which never enters the agent's environment**

## Decision

Each role has a policy TOML passed with `--admin-policy`. Agents run with a stripped environment (no GH_TOKEN),
checkout uses `persist-credentials: false`, and each job declares only the token permissions it needs.

## Consequences

- Even a fully hijacked agent cannot push, comment or approve.
- Two layers: tool policy + missing credentials.
- Agents cannot look up related issues/PRs on GitHub themselves.
- Signal to revisit: agents fail because they lack a tool they legitimately need.
