# ADR-001: Split the work into one Builder role and one independent Reviewer

**Date:** 2026-11-23
**Status:** Proposed
**Decision area:** D1 Splitting the work

## Context

The workflow must run six fixed stages and needs a reviewer that is independent of whoever wrote the code.
Agents degrade as their context fills with earlier tool output (observed in A2 traces: long sessions re-read
files and lose track of the spec). Each extra agent role adds prompts, permissions and hand-off formats to maintain.

Options considered:
1. One agent runs all six stages in one session
2. **Builder role for stages 1-4 (+ rework), separate Reviewer role for stage 6; each builder stage is a fresh headless call**
3. One agent per stage (six roles, six prompts, six permission sets)
4. Planner agent that spawns worker agents on demand

## Decision

We will use two agent roles. The Builder role runs stages 1-4 as separate fresh `gemini -p` calls that share one
policy file and one model; the Reviewer is a separate role in its own job. Stage 5 (release) is plain code, not an agent.

## Consequences

- Fresh context per stage keeps each call small and focused; artifacts are the only memory.
- Only two permission profiles to audit (builder, reviewer).
- Stages cannot ask each other clarifying questions; anything not written in an artifact is lost.
- Signal to revisit: stages repeatedly fail because a needed fact was not in the hand-off artifact.
